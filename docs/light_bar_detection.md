# 蓝色装甲板灯条检测：参数对比说明

流程：**视频读取 → 颜色分割 → 掩膜优化 → 轮廓提取 → 几何筛选 → 框选显示**

```bash
./build/visual                          # 默认 test_video2.webm -> output/
./build/visual <视频路径> <输出目录>
```

## 1. 单帧通道对比：为什么必须用色相分割

对代表帧（第 196 帧）分离通道后可以看出各通道差别（对应 `output/test_video2_pipeline_frame_0196.png`）：

| 图像 | 蓝色灯条的表现 | 结论 |
|---|---|---|
| 原图 | 蓝色灯条在暗背景上呈蓝白色细长亮条 | 目标是**颜色**特征，不是亮度特征 |
| B 通道 | 灯条最亮（灯条 B≈210），背景暗 | 蓝灯条在 B 通道对比度最高 |
| G 通道 | 灯条中等亮度（G≈135），与场地白线、白灯亮度接近 | 区分度低 |
| R 通道 | 灯条几乎全黑（R≈18），而暖色灯、白灯很亮 | **R 通道最能区分“蓝”与“暖/白”** |
| 灰度 | 灯条 Y≈0.114×210+0.587×135+0.299×18 ≈ **109**，属中等亮度；场地白线/顶部强光可达 200~255 | 灰度无法把蓝灯条与白线/过曝区分开 |

**实测色彩分布（634 帧统计）**

- 蓝灯条像素均值 BGR ≈ **(210, 135, 18)** → HSV 中 V≈210、S≈233、**H≈101~103**
- 暖色灯光色相峰值为 **H≈7~10**
- 高饱和高亮像素只占全画面的 **0.3%~0.7%**，说明画面整体很暗、目标稀疏

**结论**：选择 **HSV 色相分割**（而非灰度阈值）。判据为 `H∈[90,125]`、`S≥80`、`V≥60`：
色相区间直接排除暖色灯（H≈7~10）与白线/过曝（低饱和），S/V 下限再滤掉暗淡反光。

**静态性检验**：把 634 帧的蓝色掩膜逐像素累加，出现率 >30% 的像素仅 **39 个**，
即画面中**不存在静态蓝色结构**——蓝色只出现在运动目标上，没有静态蓝色场地灯条。
这说明真正需要额外排除的是暖色灯、白色场地线、边缘杂点，以及非“细长条”形状的蓝色反光。

## 2. 形态学对比（634 帧，其余几何条件完全相同）

| 配置 | 灯条总数 | 无灯条帧 | 掩膜均值 (px) | 形态学后轮廓数 | 平均紧贴度 |
|---|---|---|---|---|---|
| D 不使用形态学 | 2471 | 0 | 2188 | 24175 | 0.724 |
| **A 开运算 3×3（最终采用）** | **2476** | **0** | **2043** | **4631** | **0.749** |
| C 开运算 5×5 | 1726 | 0 | 1781 | 3674 | 0.815 |
| B 开运算 3×3 + 闭运算 9×9 | 2438 | 0 | 2073 | 3116 | 0.742 |

### 对比结论

**D → A（3×3 开运算）：改善明显，无目标损伤**

- 原始轮廓数 24175 → 4631（**−81%**），掩膜像素 −6.6%：清除大量孤立噪点/麻点；
- 灯条总数 2471 → **2476，不降反增**（噪点不再与目标粘连，目标被独立分离出来）；
- 平均紧贴度 0.724 → 0.749（框更贴合）；
- => **改善噪声、未损伤目标，保留该步骤**。

**A → C（5×5 开运算）：损伤目标，不采用**

- 灯条总数 2476 → 1726，**损失 750 根（−30.3%）**；逐帧比较有 **502/634 帧**检出变少；
- 原因是 5×5 核会腐蚀掉远处/较细的灯条（细至 3~8 px），
  而这类灯条正是验收要求“完整保留”的目标；
- 紧贴度虽升到 0.815，但这是“把难判的目标直接删掉”换来的，**代价不可接受 => 不采用**。

**A → B（再加 9×9 闭运算）：无增益，且让框变松，不采用**

- 灯条总数 2476 → 2438（少 38 根，相邻蓝色区域被粘连合并）；
- 平均紧贴度 0.749 → 0.742（略降）；
- 第 600 帧单帧证据：同一灯条的框由 **长 119.0 px 变为 142.4 px（+20%）**，
  紧贴度 0.673 → 0.631 —— 闭运算把周围杂散蓝色“补”进目标，导致框变大变松；
- => 既不增加检出、又降低紧贴度，**不采用**。

> 最终配置：**仅使用 3×3 开运算**；闭运算经对比明确为负收益，故不使用。

## 3. 轮廓 / 多边形近似 / 最终框选

`output/test_video2_pipeline_frame_0196.png` 的第 7、8 格展示这两个阶段：

- **第 7 格（轮廓 + 多边形近似）**：灰线为 `findContours(RETR_EXTERNAL)` 原始轮廓；
  黄线为 `approxPolyDP`（`eps = 0.02 × 轮廓周长`）的闭合多边形近似，用于观察形状。
- **第 8 格（最终框选）**：对每个通过筛选的轮廓取 `cv::minAreaRect` 旋转矩形。
  `minAreaRect` 在数学上就是**包含该轮廓的最小面积旋转矩形**，
  因此它已是对“旋转矩形”这一表示法而言最紧的框选方式。

**几何筛选条件**（全部为比例阈值，不含任何固定画面坐标或固定帧号）：

| 条件 | 取值 | 作用 |
|---|---|---|
| 轮廓面积 | `max(30 px, 2e-5×W×H) ≤ A ≤ 0.02×W×H` | 剔除边缘细小杂点、排除超大蓝色块 |
| 短边（厚度） | `≥ 2.5 px` | 排除细碎噪点 |
| 长边（长度） | `≥ 10 px` | 排除方形小块 |
| 长宽比 | `1.8 ≤ 长边/短边 ≤ 16` | 灯条是“细长条”；排除方形灯光及非条形干扰 |
| 紧贴度 | 旋转矩形内蓝色像素占比 `≥ 0.45` | 排除形状不规则或与杂散蓝色粘连的区域 |

**框选质量实测（全片 634 帧）**

- **蓝像素覆盖率 = 1.000**：灯条的每个蓝色像素都被其旋转矩形包含，**从不漏框、不切断目标**；
- 旋转矩形与轮廓的 IoU：中位数 **0.745**、最小 0.532；IoU < 0.60 的仅占 **0.65%**；
- IoU 未达到 1 是因为灯条本身不是标准矩形（边缘渐晕、倾斜、轻微弯曲），
  而 `minAreaRect` 已是同表示法下的最优（最小面积外接旋转矩形）。

## 4. 干扰排除的对照实验

用合成对照视频验证各筛选条件确实生效。画面放入 5 个目标，期望只检出 1 个：

| 放入的物体 | 期望 | 实际 |
|---|---|---|
| 蓝色灯条 12×90（长宽比 7.5） | 检出 | ✅ 检出 |
| 蓝色方块 90×90（长宽比 1.0） | 排除 | ✅ 被长宽比剔除 |
| 橙色灯条 12×90（H≈10） | 排除 | ✅ 被色相区间剔除 |
| 灰色圆（低饱和） | 排除 | ✅ 被 S/V 下限剔除 |
| 蓝色杂点 2×3 | 排除 | ✅ 被面积下限剔除 |

结果：40 帧共检出 **40 根（每帧恰好 1 根）**，其余 4 类干扰全部被正确排除。

## 5. 异常与边界情况

| 情况 | 处理 | 验证 |
|---|---|---|
| 路径/文件错误 | 打印明确错误并返回退出码 1 | `./build/visual does_not_exist.webm` → 退出码 1 |
| 无可解码帧 | 打印错误并返回退出码 1 | — |
| 视频正常结束 | 正常退出 0，并统计处理帧数 | 634/634 |
| 视频流提前结束 | 与预扫描帧数比对后给出提示 | 本次未触发 |
| 整段无有效灯条 | 仍逐帧输出（标注 bars=0）并给出提示 | 无蓝色视频验证：20/20 帧 0 根，退出码 0 |
| 单帧无有效灯条 | 画面中央标注 `no valid light bar in this frame` | 本片 0 帧（每帧均有灯条） |
